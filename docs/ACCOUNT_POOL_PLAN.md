# 账号池设计记录

本文整理 3.0.0 账号池规划及后续规则调整。原规划中的定时测试和独立积分轮换设置属于当时方案。现有实现以 `src/account-pool.ts`、`src/index.ts`、`src/shim.ts` 和[账号池使用说明](../README.md#4-账号池)为准。

## 1. 功能与模块

账号池以已保存的成员列表为操作范围。用户在每个区域选择账号并保存，插件据此执行批量测试、适用账号的签到及自动选号。

| 模块或接口 | 职责 |
| --- | --- |
| `WorkBuddyAccountStore.accounts()` | 枚举账号信息 |
| `credentialFor(accountId)` | 取得指定账号的凭据 |
| `src/account-pool.ts` | 选择测试模型、账号排序和状态规则 |
| `src/account-pool-run.ts` | 处理批量动作 |
| `src/index.ts` | 将账号池结果用于请求选号 |
| `src/shim.ts` | 对符合条件的失败执行换号重试 |

## 2. 成员与请求选号

`memberAccountIds` 默认空数组。保存后的成员参加账号池操作；空列表需要用户先选择账号。

开启账号池后，插件根据可用状态和排序规则为请求选择账号。换号结果属于运行时状态，用户保存的手动选择继续保留。关闭账号池后，插件使用手动选择的账号。

现有排序还考虑临期积分、手动顺序、总积分及凭据有效期。完整规则见 [DESIGN.md](DESIGN.md)。

## 3. 批量动作

### 3.1 测试

测试采用所选模型及输入长度。默认从该区域倍率明确为零的模型中选择上下文窗口最大者，平手时保持目录顺序。缺少倍率的模型按价格未知处理。用户可明确选择收费模型，费用从被测账号扣除。

测试请求包含 system 消息。默认输入为 25000 token，恢复时间可从响应头、响应正文及适用套餐数据中解析。结果记录对应的账号、模型和测试时间。

### 3.2 签到

插件为已保存成员中适用的国内版个人账号查询签到状态，再领取当日奖励。每个账号单独记录结果。现有版本还提供默认关闭的自动签到，完成情况按日保存。

## 4. 保存规则

账号池偏好与模型选择各有保存按钮。客户端以现有区域配置为基础合并修改，并在写入后重新读取并核对。写入失败时保留编辑内容。

测试结果和请求选号由 DSH 服务端写入运行状态，避免用户保存偏好时覆盖刚取得的测量结果。模型保存与账号池保存按顺序写入，以减少同一区域配置的并发覆盖。

## 5. 区域与界面

国内版和国际版各自保存成员、开关及测试模型。一个区域的设置用于该区域的请求。界面显示所用账号和最近结果，成员选择修改后提示保存。

界面演示见 [account-pool-demo.html](assets/account-pool-demo.html)。该页面记录规划阶段的交互，具体控件以插件版本为准。

## 6. 早期规划与现有实现的差异

| 早期项目 | 后续处理 |
| --- | --- |
| `rotateByCredits` | 与请求选号整合，由账号池启用状态控制 |
| `autoTestIntervalMinutes` | 原定时测试方案被替换，按当前请求和手动测试更新状态 |
| 自动选号写入用户选择 | 运行时结果与保存的手动选择分别管理 |
| 仅手动签到 | 后续增加默认关闭的自动签到 |
| 固定 DeepSeek 为测试模型 | 改为按区域目录选择免费模型，允许明确指定 |

原规划曾以 30 分钟为定时测试默认间隔，并讨论 5 分钟下限。这些数字用于记录旧方案，配置应参照现有 schema。

## 7. 验证重点

先检查成员范围与免费模型选择，再验证账号恢复和区域隔离，最后确认保存失败时仍保留编辑内容。测试还应覆盖换号后的扣分归属、手动选择恢复和每个账号的批量操作结果。

相关文件包括 `tests/account-pool.spec.ts` 及以 `pool` 命名的路由与客户端测试。积分日志的格式及账号关联见 [CREDIT-JOURNAL.md](CREDIT-JOURNAL.md)。
