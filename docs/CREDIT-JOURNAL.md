# 响应积分日志

插件从 WorkBuddy 响应的 `usage.credit` 字段读取扣分，再将扣分、响应标识和处理请求的账号写入日志。日志路径为 `DSH_HOME/storages/dsh-connect-workbuddy/response-credits.jsonl`。

状态栏读取程序先从会话中取得响应标识，再用这些标识匹配日志记录并汇总积分。账号发生轮换时，仍按响应标识归入对应会话。

## 1. 记录格式

每行保存一条 JSON 记录：

```json
{"v":1,"r":"response-example","c":0.12,"a":"account-example","t":1793808000000}
```

| 字段 | 含义 |
| --- | --- |
| `v` | 日志格式版本，目前为 1 |
| `r` | WorkBuddy 返回的响应标识 |
| `c` | 本次响应的 `usage.credit`，可以为 0 |
| `a` | 处理本次请求的账号标识 |
| `t` | 写入日志的时间戳，单位为毫秒 |

读取程序先按响应标识去重，再将记录关联到会话。日志中的账号标识采用插件现有的账号标识算法。

## 2. 账号轮换与重试

每条日志记录处理该次请求的账号。账号池换号后，新请求的积分记在新账号下。

工具调用格式恢复可能触发重试。原响应和重试响应各自记录扣分；重试期间发生换号时，插件记录处理重试请求的账号。

## 3. 异常处理

插件仅写入具有响应标识的有效扣分记录。积分必须为有限的非负数值，允许为零。

日志写入失败时，插件输出错误日志，并继续向会话转发响应。

## 4. 验证记录

记录测试覆盖了零积分、无效字段和写入异常，并检查账号池换号、工具调用恢复重试中的积分归属。

```sh
pnpm run typecheck
pnpm run build
pnpm test
```
