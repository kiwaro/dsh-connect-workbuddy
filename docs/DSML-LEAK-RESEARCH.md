# DSML正文泄漏调查

记录日期为2026-10-01。调查对象是模型在可见正文中输出工具标记，随后客户端未取得结构化工具调用的情况。恢复设计见 [DSML-RECOVERY-PLAN.md](DSML-RECOVERY-PLAN.md)。

## 1. 解析条件

所查形态包括缺少tool_calls包裹而仍有完整invoke的输出，以及工具名或参数标签损坏的输出。手动补齐包裹的解析器对照可用于区分生成内容与解析入口问题。

## 3. 恢复条件

恢复过程需要同时确认以下信息：

1. invoke结构已经闭合。
2. 工具名属于本次请求声明。
3. 请求允许相应工具调用。
4. 参数满足工具声明的校验条件。

截断或校验失败的内容按正文处理，流式缓冲在结束时需要明确提交或回退。这样可以区分工具语法讨论和可执行调用。

## 4. 模块职责

`src/markup-diagnosis.ts` 用于分类和统计输出，`src/dsml-recovery.ts` 在响应路径中恢复工具调用。后者参考并移植 `hawklithm/workbuddy2api` 的解析器，许可说明见 [第三方声明](../THIRD_PARTY_NOTICES.md)。

5.12.2增加受限的近似名称处理：候选工具来自本次声明，名称长度至少4，仅有唯一的单字符编辑距离候选时可恢复。参数名按原声明校验。

## 5. 检测记录

原捕获同时包含单竖线和双竖线写法，并出现参数标签而工具名损坏的情况。诊断器因此检查兼容竖线和参数片段，同时识别行内引用。

| | 修正前 | 修正后 |
|---|---|---|
| 判定为「正文里发出」 | 6 次 / 2 个会话 | 12 次 / 4 个会话 |
| 其中本会话 | 0 次（完全看不见） | 5 次 |
| 单独计为「只是在讨论/引用」 | 0 次 | 13 次 |

当时增加9项检测测试，分别回退竖线、参数和反引号识别的变异能够触发失败。

## 6. 对照方法

定位时分别改变流式模式、tool_choice、上下文长度和并发，保持其他输入固定。再根据需要比较权重、运行时或完整客户端流程。

验证材料应包括请求工具声明、原始响应、shim输出和实际执行结果。正文标记数量用于诊断，可恢复调用是否进入结构化通道用于判断恢复行为。
