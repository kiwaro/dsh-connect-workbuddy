# 图片生成与改图

本页说明图片工具的参数、参考图要求及生成结果的读取方式。

工具 `workbuddy_draw_image` 使用已授权区域的 WorkBuddy 账号生成图片。开启区域及“允许模型调用图片生成工具”后，会话模型即可调用该工具。两个区域都符合条件时，插件优先选择国内版账号。

一次调用生成一张图片，并按所用区域和模型扣除积分。响应中的 `credit` 表示服务端报告的该次扣分，未与独立账单核对。2026-10-21 至 2026-10-25 的测量记录放在第 6 节。

## 1. 参数与操作

文生图必须提供 `prompt` 和 `size`，可选 `model`。改图增加 `image` 字符串数组；即使只有一张输入图，也必须使用数组。插件按数组顺序处理参考图。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `prompt` | 字符串，必填 | 描述主体、构图、风格和光线 |
| `size` | 字符串，必填 | 使用正整数 `宽x高`，分隔符接受 `x`、`X`、`×`；改图还可用 `auto`，无默认值 |
| `model` | 字符串，可选 | 选择当前区域、当前生成模式支持的模型 |
| `image` | 非空字符串数组，可选 | 输入图或多张参考图，例如 `["/abs/input.png"]`；纯文生图省略该字段 |

可选参数可省略。`asImageList()` 拒绝字符串、空数组及包含空字符串或非字符串元素的数组。`rejectUnknownArgs()` 仅允许 `prompt`、`size`、`image`、`model`；`ratio`、`n`、`return_base64` 等未知字段和错误类型均返回 `INVALID_ARGS`，不会提交生成请求。

`parseSizeSpec()` 校验格式，`planImageSize()` 决定最终画布。两条边必须在 512–2560 像素内，面积不超过 `MAX_IMAGE_PIXELS = 4_194_304`。范围外的尺寸由 `fitIntoRange()` 等比缩放，并经面积复查；极端比例无法等比放入范围时返回 `INVALID_ARGS`。`size: "auto"` 需要能够读取输入图尺寸；无法读取时要求明确尺寸，比例过于细长时可采用常用画布，并在 `hint` 说明比例变化。

插件只调整输出画布，保留输入图片字节。`buildImageBody()` 接收到的是已经确定的最终 `size`。常用尺寸为方图 `1024x1024`、竖图 `1024x1536`、横图 `1536x1024`；历史上游直接拒绝的尺寸见第 6.1 节，该表不表示当前工具也会直接提交这些越界值。

例如 `4096x4096` 会被调整为 `2048x2048`；结果中的 `size` 表示最终画布，`requestedSize` 表示调整前的值，`hint` 说明变化。工具没有 `seed` 或历史重放接口，同一 `prompt` 重复调用不保证得到相同图片。

## 2. 输入图片

插件先读取或下载图片，再编码为 data URL。每张图由 `assertInputImageBytes()` 按解码后的字节数检查，大小上限为 `MAX_INPUT_IMAGE_BYTES = 8 * 1024 * 1024`（8 MiB）；空文件也会被拒绝。插件保留原图的尺寸、格式及像素内容。

| 输入形式 | 处理方式 |
| --- | --- |
| 绝对文件路径 | 读取文件 |
| `file://` URL | 转为文件路径后读取 |
| `http(s)` URL | 使用 GET 下载，超时为 30 秒 |
| data URL | 检查图片类型和 base64 内容 |
| base64 字符串 | 校验后解码 |
| 字符串数组 | 按数组顺序处理每张图片 |

图片类型优先采用 HTTP `Content-Type`，其次采用扩展名和文件头识别结果。支持识别 PNG、JPEG、GIF、WEBP 和 BMP；缺少类型时使用 `image/png`。

插件对文件读取和图片下载进行检查，并校验格式及大小。这些检查失败时返回 `INVALID_ARGS`，修正输入后可立即重试。

## 3. 模型选择与目录

文生图使用 `text-to-image` 标签组，改图使用 `image-to-image` 标签组。提供 `model` 时，插件检查该模型是否属于对应标签组；省略时，插件选择组内第一个模型。

媒体目录来自 WorkBuddy 产品配置。插件单独读取并缓存 5 分钟，设置页的“重新读取”可请求刷新。接口为 `POST /plugins/dsh-connect-workbuddy/media-models`，用于返回媒体模型信息。

2026-10-25 的记录中，国内版的文生图和改图模型分别为 `hunyuan-image-alpha`、`hunyuan-image-alpha-edit`，国际版的 `hy-image-3.5` 同时属于两个标签组。调用时使用所选账号返回的目录。

## 4. 请求、输出与错误

| 模式 | 端点 |
| --- | --- |
| 文生图 | `POST /v2/images/generations` |
| 改图 | `POST /v2/images/edits` |

请求头由 `src/upstream.ts` 中的 `imageHeaders()` 构造，具体字段还受请求标识配置影响。`buildImageBody()` 按模型类型构造请求：hunyuan 系列添加 `n: 1`，gemini 系列采用基础字段，其他模型可包含 `response_format: b64_json`。

插件先解析业务码，再读取图片 URL 或 base64 数据。base64 图片保存到系统临时目录的 `workbuddy-image-gen/` 下，文件名包含模型和时间戳。

| 输出字段 | 含义 |
| --- | --- |
| `url` | 图片 URL 或 `file://` URL |
| `mode` | `generate` 或 `edit` |
| `region` | 实际使用的区域：`cn` 或 `global` |
| `size` | 实际提交的画布尺寸，使用小写 `宽x高` |
| `requestedSize` | 画布调整或使用 `auto` 时记录的原始尺寸要求 |
| `model` | 所用模型标识 |
| `prompt` | 提交的图片描述 |
| `hint` | 显示方式及链接有效期说明 |
| `credit` | 服务端返回的扣分，可能缺失 |
| `path` | 保存图片时的绝对文件路径 |

COS 签名 URL 的历史测量有效期约为 24 小时。长期保留图片时，应在链接有效期内下载。

| 错误类别 | 处理方式 |
| --- | --- |
| `INVALID_ARGS` | 修正参数或输入图片 |
| `AUTH` | 更新登录凭据 |
| `NO_ROUTE` | 检查区域是否提供图片接口 |
| `RATE_LIMIT` | 稍后重试 |
| `UPSTREAM`、`EMPTY_RESULT` | 根据服务端错误及响应内容排查 |

工具独占执行，`IMAGE_TOOL_TIMEOUT_MS = 180_000`；目录缓存为 `MEDIA_MODEL_TTL_MS = 5 * 60_000`，远程输入图超时为 `IMAGE_INPUT_TIMEOUT_MS = 30_000`。请求已发出后的适用失败会触发 30 秒冷却；参数、登录和模型目录检查在请求前完成。

## 5. 凭据与验证

工具在 DSH 端取得账号凭据并发送请求，输出返回图片及业务结果。相关实现为 `src/image-tool.ts`、`src/image-gen.ts` 和 `src/upstream.ts`。

测试检查模型选择、请求体、图片读取和大小校验，以及错误分类、冷却、输出格式和区域授权。测试文件为 `tests/image-gen.spec.ts` 和 `tests/image-tool-optin.spec.ts`。

视频生成的异步流程见 [VIDEO_GEN.md](VIDEO_GEN.md)。

## 6. 历史测量

测量使用插件 4.13.2，源码提交 `dfe7ab3`。国内版记录的单张费用为 5.71 积分，国际版为 0.03 积分，两项测量使用不同区域和模型。

国内版一次调用返回 HTTP 200，耗时 12.9 秒，图片大小为 2065707 字节，PNG 文件头为 `89-50-4E-47-0D-0A-1A-0A`，尺寸为 1024×1024，右下角有 WorkBuddy 生成标记。其他单张调用记录的耗时范围为 12.9 至 38.7 秒。

国际版 `hy-image-3.5` 返回 COS 签名 URL，使用新加坡区域的存储桶。该次接口检查记录为 `/v2/api-keys` 返回 503，`/agenttool/v1/tempkey` 返回 500；国内版后一个接口返回 200。这些记录属于各自接口的测量结果。
