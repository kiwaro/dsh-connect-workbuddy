# issue #184：会话缓存命中率

本记录整理原缓存调查的主要数据。完整脚本与测量过程见 [CACHE-HIT-70-RESEARCH.md](CACHE-HIT-70-RESEARCH.md)。各百分比采用对应调查材料中的输入 token 统计。

## 1. 统计方法

会话页面计算缓存命中率时，分母为未缓存输入、缓存读取和缓存写入之和，分子为缓存读取。会话值采用日志中的累计加权统计。

```text
缓存命中率 = cacheReadTokens / (uncachedInputTokens + cacheReadTokens + cacheWriteTokens)
```

## 2. 模型与会话记录

| 模型 | 请求数 | prompt token | 命中率 |
| --- | --- | --- | --- |
| deepseek-v4.1-flash | 13,282 | 3,157,473,803 | 97.9% |
| space-bunny | 862 | 132,648,250 | 99.0% |
| hy4-preview | 76 | 3,956,243 | 96.3% |
| hy3 | 27 | 1,011,059 | 89.0% |
| glm-5.3-flash | 18 | 554,017 | 77.1% |
| minimax-m3.1-flash | 278 | 25,136,718 | 44.6% |
| 全机加权 | 14,543 | 3,320,780,090 | 97.5% |

整组数据的加权命中率为 97.5%。其中不同模型的命中率差异较大，混合模型会话的累计值还受到各模型输入量占比影响。

同一凭据、相同请求连续执行 6 次，DeepSeek 的记录均约 97%；MiniMax 的记录为 2%、2%、2%、0%、0%、2%。输入从约 23K 增至 26K 的四轮对照中，DeepSeek 后三轮为 94.9%、95.4%、95.4%，MiniMax 为 0.5%、0.8%、0.7%。

该测量反映所用模型和后端的缓存表现。多后端实例缺少同一会话是否持续使用相同后端是一种解释，仍需要后端资料支持。

## 3. 账号切换

同一分钟内，用相同请求对照两个账号：

```text
A warm : prompt=8412 hit=8192 (97.4%)
A same : prompt=8417 hit=8192 (97.3%)
B same : prompt=8417 hit=0    (0.0%)
A ctrl : prompt=8417 hit=8192 (97.3%)
```

这组结果表明该次缓存按账号隔离。评估账号池对会话命中率的影响时，需要统计实际换号次数。

原混合模型测算使用 DeepSeek 0.979 和 MiniMax 0.446：达到 0.70 的加权值时，MiniMax 占约 52.3% 输入量。另一组测算中，冷请求占 28.5% 可使平均命中率约为 70%；原 DeepSeek 数据中冷请求约占 1%。

## 4. 工具注册变化

调查记录了同一会话中 system 文本和工具列表的变化：

| turn | system 长度 | 同期工具事件 | 该 turn 命中率 |
| --- | --- | --- | --- |
| 1 | 13,512 | 首次挂载 | 88.3% |
| 5 | 39,092 | 新增 8 个工具，含 `purge_apply` / `team_task_*` | 85.3% |
| 6 | 13,562 | +`create_worktree` / `session_search` 等 | 0.0% |
| 8 | 10,204 | −2 个工具 | 0.0% |
| 9 | 10,011 | +`bsk_*` 全套 + `mcp` 全套 | 0.0% |
| 10 | 13,834 | +`acp_*` / `compress` / `render_ui` 等 | 0.0% |
| 12–37 | 未再变化 | 无 | 96–99.5% |

工具注册事件会影响发送的前缀。定位命中率下降时，应同时检查 `source.kind: tool-registry` 事件、system 文本版本及模型和账号切换。

## 5. 消息重排选项

当时对 `keepPromptLast` 的对照中，关闭时相邻请求前缀保留率为 100%；开启时的三条记录为 98.6%、98.8%、98.9%。20 轮、每轮 4 步的 79 次请求统计为 98.26% 对 100.00%，差异为 1.74 个百分点。

两个会话的 386 个步骤中记录到 12 条上下文自动添加。上述小样本需要与目标会话的实际请求频率比较。

## 6. 排查所需资料

分析具体会话时，收集使用过的模型、账号切换记录、工具注册变化和请求 usage 计数。共享材料前移除提示正文和账号凭据。

后续测试应检查跨请求前缀稳定性，包括消息重排的重复执行是否会改变结果。原材料将此项列为后续工作，处理具体版本时需要再次检查实现。
