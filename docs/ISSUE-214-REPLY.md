# issue #214：目录刷新与积分倍率

本记录对应上游对 5.18.0 目录倍率问题的调查。报告比较了刷新接口、积分页面和配置文件的数值，并发现 `glm-5.3` 与 `hy4-preview` 的显示值未同步更新。

## 1. 发现的问题

当时 `applySelection` 已检查动态目录状态，但 `/usage` 使用的 `displayModels()` 仍可能将静态目录当作动态结果。国际版静态表中的倍率覆盖了已经保存的目录信息，出现 0.79 与 0.69、0.00 与 0.29 的差异。

另一个问题在 `models/refresh`：路由返回刷新所得模型，却未保存目录，因此页面刷新后又读取到旧值。

## 2. 修改规则

静态目录保留模型标识、名称和窗口信息。费率由接口或已经保存的目录提供；缺少倍率时省略显示，免费模型选择严格使用明确为零的倍率。

刷新路由先保存目录，再返回结果。保存失败返回错误。模型勾选和图片输入设置通过保存按钮提交；上下文预算与默认推理强度也采用这一保存方式。

## 3. 验证

`tests/issue214-fallback-price.spec.ts` 的原始记录为 9 项测试，覆盖上游尚未返回时采用保存倍率，以及刷新后接口和文件一致。

核对以下三处：

1. `POST /plugins/dsh-connect-workbuddy/models/refresh?region=global`。
2. `GET /plugins/dsh-connect-workbuddy/usage?region=global`。
3. `cordis.patch.yml` 中的 `regions.global.lastCatalog`。

同一模型在三处的目录倍率应一致。

## 4. 其他调查内容

报告还提出了 `11102`、`11103` 的模型可用性处理。当次修改仅处理目录及费率来源，该项需要单独核对模型调用结果。

同一产品配置接口在不同 User-Agent 下可能返回不同费率。报告中的 0.11 与 0.03 对照应随客户端标识一同记录；调用扣分通过响应中的 `credit` 检查。
