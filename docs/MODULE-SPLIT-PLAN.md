# 核心模块拆分方案与执行记录

本文保留模块拆分及后续修复的历史批次记录。各节中的“本轮”和测试数量仅指该节对应批次；后续文档修订与验证范围另见 [文档语言检查记录](DOCUMENT-LANGUAGE-REVIEW-2026-11-09.md)。

## 1. 目标与约束

本次重构将 src/index.ts、src/auth.ts、src/shim.ts、src/adapter.ts 和 src/client/WorkBuddyCard.tsx 中的职责提取为独立模块。各模块分别负责配置、凭据解析与持久化、请求传输与流恢复、消息转换，以及界面展示与状态管理。原入口继续保留对外导出，重构后的配置字段、请求处理顺序、账号选择、重试次数、界面操作和持久化格式须与原实现兼容。维护者执行重构时须保留工作区中已有的改动。

各批次完成后，原文件应只保留对应的装配或协调职责，新模块不得在运行时反向导入入口。维护者须确认受影响测试、完整类型检查、全量测试、构建和安装入口检查均通过，再部署本机构建产物，并记录实际运行验证的条件与结果。

## 2. 批次

1. 请求服务：分离端口生命周期、HTTP 请求与错误处理、流恢复；核对换号和重试状态仍由请求协调层统一管理。
2. 模型适配：分离模型身份与描述、历史消息兼容与思考块处理；适配器保留注册和流调用装配。
3. 凭据：分离平台路径、凭据解析与账号标识、凭据文件持久化；账号仓库保留扫描与刷新协调。
4. 插件入口：分离配置类型与 schema、区域配置解析、状态与服务注册；入口保留服务生命周期装配。
5. 设置界面：分离展示格式与诊断结果、设置分区和数据状态；主卡片保留区域选择与组件组合。
6. 交付：运行完整检查，核对原导出与依赖方向，更新设计说明，备份部署并验证安装入口。运行中 DSH 的重启需评估当前工作及已有不兼容插件影响。

维护者应根据实际依赖确定模块数量，不应只为缩短文件而拆分。源码文本断言如果仍依赖旧文件位置，维护者应将其迁移到实际承担职责的新模块，或改为验证相应行为，同时保留原有约束。

## 8. 末位备用账号规则

该批次根据用户确认的账号顺序规则实现末位备用机制，不按会员身份分类。插件在请求前选号、失败换号和状态查询中统一启用 `rankPool` 的 `reserveLast` 选项。账号池至少包含两个有效成员时，插件才设置末位备用账号；用户未设置独立顺序时，插件使用已保存的成员顺序。只有全部前序成员均为零余额，或具有仍有效的限流、积分耗尽记录时，插件才启用备用账号。前序成员余额未知或因其他原因失败时，备用账号继续保持停用。

新增四项排序回归覆盖末位不因临期积分提前启用、全体前序受限后的启用、未知和其他错误不解锁、限流恢复后的重新锁定。更新集成断言，验证界面候选与实际路由保持一致；选号读取失败测试改为断言停止上游请求。失败记录在换号前等待完成，并防止重复记录。
