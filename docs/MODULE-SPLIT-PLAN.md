# 核心模块拆分方案与执行记录

本文保留模块拆分及后续修复的历史批次记录。各节中的“本轮”和测试数量仅指该节对应批次；本次文案审核与本机部署结果另见 [文档同步审核记录](DOCUMENT-SYNC-AUDIT.md)。

## 1. 目标与约束

拆分 src/index.ts、src/auth.ts、src/shim.ts、src/adapter.ts 和 src/client/WorkBuddyCard.tsx。按配置、凭据解析与持久化、请求传输与流恢复、消息转换、界面展示与状态管理分配职责。原入口保留对外导出；配置字段、请求处理顺序、账号选择、重试次数、界面操作与持久化格式保持兼容。保留现有工作区改动。

完成条件：各批次实际提取职责模块，原文件仅保留对应装配或协调职责；核对依赖方向，避免通过运行时反向导入入口；受影响测试、完整类型检查、全量测试、构建及安装入口检查通过；部署本机构建产物并记录运行验证条件。

## 2. 批次

1. 请求服务：分离端口生命周期、HTTP 请求与错误处理、流恢复；核对换号和重试状态仍由请求协调层统一管理。
2. 模型适配：分离模型身份与描述、历史消息兼容与思考块处理；适配器保留注册和流调用装配。
3. 凭据：分离平台路径、凭据解析与账号标识、凭据文件持久化；账号仓库保留扫描与刷新协调。
4. 插件入口：分离配置类型与 schema、区域配置解析、状态与服务注册；入口保留服务生命周期装配。
5. 设置界面：分离展示格式与诊断结果、设置分区和数据状态；主卡片保留区域选择与组件组合。
6. 交付：运行完整检查，核对原导出与依赖方向，更新设计说明，备份部署并验证安装入口。运行中 DSH 的重启需评估当前工作及已有不兼容插件影响。

模块数量按实际依赖确定，避免只为缩短文件而拆分。发现源码文本断言依赖旧文件时，改为检查新职责模块或行为，同时保留原约束。
